# 验收与交接

## 验收范围

- 新增 Agent 原生对象的生成、校验、导出与门禁行为。
- 既有 3.x 行为的回归安全。
- 文档、版本号与升级路径的一致性。

## 验收标准

- AC-001（REQ-001）：初始化后生成 `.specnfc/skill-packs/active/skills/<name>/SKILL.md`，`skills validate` 通过；非法 frontmatter 返回非零并给出错误。
- AC-002（REQ-002）：初始化后生成 MCP 策略；通配符工具授权或 untrusted server 无审批写操作被 `doctor / ci` 阻断。
- AC-003（REQ-003）：初始化后生成角色目录与角色文档；`agents validate` 通过，阶段覆盖完整，可导出为子代理定义。
- AC-004（REQ-004）：`agents task` 生成带 traceId、预算、验收标准与 worktree isolation 的任务契约。
- AC-005（REQ-005）：`eval run` 在默认配置通过；加入失败用例后返回非零，并落盘结果文件。
- AC-006（REQ-006）：默认权限清单有效；改为默认允许、全仓写、危险命令或无边界网络后 `security check` 返回非零。
- AC-007（REQ-007）：AGENTS.md 包含标准 section 与关键引用；超过 400 行被 `doctor` 标记为 invalid。
- AC-008（REQ-008）：change 模板生成 `REQ / AC / TASK / EV` 编号；`trace` 输出完整矩阵；删除证据后 `--strict` 返回非零。

## 剩余风险与结论

- 风险 1：默认 MCP 策略没有真实 server，团队首次接入时需要按自身工具清单补充。
- 风险 2：eval 断言目前是字符串与文件存在性级别，后续可扩展 JSONPath / 结构化断言。
- 风险 3：角色工具名使用通用名称（Read / Edit / Bash），不同代理需要映射到自身工具名。
- 是否满足当前阶段要求：是
- 是否允许进入 handoff / archive：是，可进入 handoff；建议先在 1–2 个真实仓灰度后再归档。
